# Slides

Slide decks written in Markdown and converted to HTML with [Marp](https://marp.app).

**Never read, open, print, or search any `.env` file (or its contents) in any way, including with `cat`, `grep`, `source`, or scripts that echo it.** It holds API keys. This is strictly forbidden, with no exceptions. Only `scripts/refactor.py` loads it, at run time.

- `<course>/*.md`: slide sources (e.g. `ap-cyb/dns.md`); the `.html` next to each is Marp's output.
- `index.html`: hand-written landing page for slides.manzano.dev; `make build` copies it to `build/index.html`. It's only a general description of the site and deliberately doesn't link to individual decks, so it doesn't need updating when decks are added, renamed, or removed.
- `templates/`: starter `.md` files to copy into a course folder (e.g. `peer-instruction.md`: a question with four A–D answer boxes). The Makefile skips this folder, so templates are never built or deployed.
- `themes/`: custom Marp themes (set via `.marprc.yml`). Marp inlines them into the HTML, so the CSS isn't deployed. `main.css` turns numbered lists into A–D answer boxes following `COLORS.md`; a slide whose list is a real numbered sequence opts out with `<!-- _class: numbered -->`. `<!-- _class: best-answer -->` and `<!-- _class: wrong-answer -->` add a bottom banner telling students which kind of answer to submit (starter in `templates/answer-modes.md`); the mode is only on the slide, not in the questions JSON.
- `make build`: rebuilds decks whose `.md`, a theme, or `.marprc.yml` changed and copies the HTML into `build/`, keeping the folder layout, along with any `images/` files the decks reference. It also runs `scripts/extract_questions.py`, which writes `build/<deck>.questions.json` for decks with question slides and fails the build on an invalid one.
- Question slides: a `<!-- question ... -->` comment holds an optional `ask:` and one or more `answer:` lines, any of which is accepted (format in `scripts/extract_questions.py`). It marks a slide for the separate response app, which fetches the JSON from the deployed site. Answers are deliberately public: they show in presenter notes and the JSON. Each question's `id` is generated from its wording and options, so changing those starts a new question in the app.
- `templates/slide_extraction.md`: guide for the LLM working on the response app, with `templates/model-example.md` and its generated `model-example.questions.json` as the fixture. `make build` regenerates that JSON. Update the guide and fixture if the JSON format or question format changes.
- `make test`: runs `make build`, then serves `build/` locally with `python3 -m http.server` to preview.
- `make refactor`: runs `scripts/refactor.py` (in `.venv`) over every deck, replacing ```` ```llm:image ```` blocks (`prompt:`, `alt:`, optional `marp:` keywords like `bg right`; without them an image alone on its slide gets `bg contain`, otherwise `h:450`, so it fits) with an OpenAI-generated image in `images/<deck>/`, and ```` ```llm:slide ```` blocks (`prompt:`) with a whole slide written by Claude. Decks are regex-scanned first, so no API is called when there's nothing to replace. Keys `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` go in `.env` (git-ignored).
- `make deploy`: runs `make build`, deletes each deck's `.html` once its copy in `build/` matches (so the next build regenerates every deck; `index.html` is kept), then `git add .`, commits with the current date and time as the message, and pushes.
- `build/`: what gets deployed. GitHub Actions (`.github/workflows/main.yml`) uploads it to Cloudflare with `wrangler deploy` on every push to `main` (see `wrangler.toml`), using the `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` repository secrets.
